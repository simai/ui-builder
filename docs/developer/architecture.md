# Architecture and ownership

## Repository boundaries

| Layer | Repository | Responsibility |
| --- | --- | --- |
| Framework source | `simai/ui-source` | Canonical SCSS, JavaScript, templates, and metadata for Core, Component, Utility, and Smart |
| Build system | `simai/ui-builder` | Build planning, Webpack configuration, deterministic lifecycle, diagnostics, and packaging |
| Core and Component distribution | `simai/ui` | Generated output |
| Smart distribution | `simai/ui-smart` | Generated output |

Generated repositories are never the source of a fix. A change starts in
`ui-loader` or `ui-builder`; distributions are updated only through a
reproducible build followed by independent acceptance.

## Build lifecycle

1. `buildPlan` creates a deterministic source inventory and rejects path
   collisions, escaping paths, and unsafe symbolic links.
2. `webpackConfigFactory` creates normal and minified configurations that share
   the RTL-safe PostCSS policy. The policy preserves each physical fallback
   immediately before its logical CSS-variable declaration and removes only a
   redundant late directional fallback generated by PostCSS. Author overrides
   and the LTR/RTL declarations themselves remain untouched.
3. `productWebpackRuntime` binds separate builder and source dependency roots
   and configures stable module and chunk identifiers.
4. A product runner executes the compiler lifecycle exactly once and writes
   structured diagnostics.
5. `generatedPackaging` materializes templates and assets, produces
   deterministic gzip files, and applies digest-bound legacy compatibility when
   explicitly requested.
6. The reproducibility verifier compares file manifests from two isolated build
   waves and fails on any byte-level difference.

## Determinism and safety invariants

- Logical CSS declarations remain after direction-aware physical fallbacks.
- Late generated fallbacks cannot override variable-powered borders, colors,
  spacing, or positioning in either direction.
- Input, output, and dependency runtime roots are absolute.
- The output root is new and is outside the source tree.
- Build plans and generated bytes do not depend on temporary directory names.
- Source checkouts and existing generated repositories are not modified by
  verification.
- Partial or mismatched legacy compatibility bindings fail closed.
- Output collisions and unsupported filesystem entries fail closed.
- One successful build is not evidence of complete framework RTL readiness.

## Compatibility boundary

The repository supports both modern `build:*` commands and the accepted legacy
command surface. Compatibility preserves existing consumers, but new automation
should use product runners and explicit verification commands. See
[Migration from the legacy builder](migration-from-sf5-webpack.md).
