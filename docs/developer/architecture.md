# Архитектура ui-builder

## Ownership

| Контур | Репозиторий | Роль |
| --- | --- | --- |
| Framework source | `simai/ui-loader` | canonical SCSS/JS/templates Core, Component, Utility, Smart |
| Build system | `simai/ui-builder` | planning, Webpack configs, deterministic lifecycle, packaging |
| Core/Component distribution | `simai/ui` | generated output |
| Smart distribution | `simai/ui-smart` | generated output |

Generated repositories не являются источником исправлений. Изменение должно
начинаться в `ui-loader` или `ui-builder`, после чего distributions обновляются
только воспроизводимой сборкой и отдельной acceptance.

## Build lifecycle

1. `buildPlan` делает deterministic inventory и отклоняет collisions,
   escaping paths и небезопасные symlinks.
2. `webpackConfigFactory` создаёт normal/minified конфигурации с общей RTL-safe
   PostCSS policy.
3. `productWebpackRuntime` привязывает независимые builder/source dependency
   roots и stable module/chunk IDs.
4. Product runner выполняет compiler lifecycle ровно один раз и пишет typed
   diagnostics.
5. `generatedPackaging` материализует templates/assets, deterministic gzip и
   digest-bound legacy compatibility.

## Invariants

- logical CSS declarations остаются после физических fallbacks;
- input/output/runtime roots абсолютны;
- output root новый и не находится внутри source;
- build plan и generated bytes не зависят от temporary root names;
- source checkout и generated repositories не изменяются проверками;
- partial compatibility binding запрещён;
- один зелёный build не является общей RTL readiness.
